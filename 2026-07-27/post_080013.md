Original Article: https://www.bleepingcomputer.com/news/security/github-pypi-add-time-absed-defenses-against-supply-chain-attacks/

**1) What happened:**

GitHub and PyPI have implemented new time-based defenses to mitigate the risks of supply chain attacks within software package ecosystems. GitHub’s Dependabot now includes a default three-day cooldown period for package updates, allowing time for newly published packages to be examined for malicious content before automatic updates occur. Meanwhile, PyPI introduced a policy that blocks the addition of new files to a package release after 14 days, protecting against the insertion of malicious code into trusted releases. These measures follow several high-profile supply chain attacks targeting these platforms.

**2) Why it matters:**

The steps taken by GitHub and PyPI are significant because they directly address the persistent threat posed by supply chain attacks, where malicious actors exploit the trust in software dependencies to insert harmful code. Such attacks can have wide-ranging impacts, potentially affecting thousands of applications and services that rely on these platforms. By implementing time-based defenses, these platforms aim to reduce the risk of compromised packages being inadvertently integrated into software projects, thus enhancing the security posture of development environments and protecting the broader software supply chain.

**3) What actions should be taken:**

Developers and organizations using GitHub and PyPI should review and adjust their development workflows to accommodate the newly introduced time-based delays and restrictions. They might consider configuring custom cooldown periods with Dependabot if different timings better fit their risk management strategies. Implementing additional measures, such as dependency pinning with lockfiles, using restricted-scope tokens, and disabling unnecessary scripts in continuous integration (CI) environments, is advised to further safeguard against supply chain compromises. Regular security reviews and awareness of these new protective measures should be integrated into development best practices.
